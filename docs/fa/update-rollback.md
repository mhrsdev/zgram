# به‌روزرسانی و بازگشت (Rollback)

<div dir="rtl">

داده‌ها روی volume با نام `zerogram_zerogram-data` هستند و با به‌روزرسانی image دست‌نخورده می‌مانند.

## به‌روزرسانی

1. **پشتیبان بگیرید** (چند ثانیه سرور را خاموش می‌کند):
   ```sh
   ./scripts/backup.sh
   ```
2. image جدید را بیاورید و اجرا کنید:
   ```sh
   ./scripts/update.sh zerogram-image.tar.gz     # بستهٔ آفلاین جدید
   # یا، اگر از روی سورس می‌سازید:
   git pull && ./scripts/update.sh
   ```
   اسکریپت image قبلی را با برچسب `zerogram:previous` نگه می‌دارد، سرور را با SIGTERM به‌صورت مرتب خاموش می‌کند (شمارنده‌ها و صف روی دیسک نوشته می‌شوند) و نسخهٔ جدید را بالا می‌آورد.
3. بررسی: `docker compose ps` باید `healthy` نشان دهد و `./scripts/connect-link.sh` باید همان لینک قبلی را بدهد (کلید سرور تغییر نمی‌کند).

## بازگشت

```sh
./scripts/rollback.sh
```

image قبلی دوباره اجرا می‌شود. volume دست نمی‌خورد. اگر نسخهٔ جدید فرمت داده را تغییر داده باشد (در یادداشت‌های انتشار ذکر می‌شود)، به‌جای آن از پشتیبان بازگردانید:

```sh
./scripts/restore.sh backups/zerogram-AAAAMMDD-HHMMSS.tar.gz
```

## نکته‌ها

- کلید RSA سرور و `ZEROGRAM_MASTER_KEY` را عوض نکنید؛ در غیر این صورت همهٔ کلاینت‌ها باید دوباره راه‌اندازی شوند و secretهای TOTP خوانده نمی‌شوند.
- پس از ری‌استارت، شناسهٔ پیام و `pts` هرگز عقب نمی‌روند (حتی بعد از توقف ناگهانی): هر راه‌اندازی پس از خاموشی نامرتب، شمارنده‌ها را با جهش ثابت جلو می‌برد.
