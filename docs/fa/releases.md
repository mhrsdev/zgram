# انتشار نسخه و به‌روزرسانی خودکار برنامه

<div dir="rtl">

برنامه به‌صورت اختیاری Releaseهای مخزن عمومی [`mhrsdev/zgram`](https://github.com/mhrsdev/zgram) را بررسی می‌کند. اگر نسخهٔ جدیدتری باشد، پنجرهٔ «نسخهٔ جدید موجود است» و در «تنظیمات» یک ردیف «به‌روزرسانی موجود است» با دکمهٔ «به‌روزرسانی» نمایش می‌دهد.

> **این بخش با فرض «بدون اینترنت بین‌الملل» ناسازگار نیست چون اختیاری است:** بررسی در پس‌زمینه با ۲۰ ثانیه تأخیر انجام می‌شود، اگر GitHub در دسترس نباشد بی‌صدا رد می‌شود و هیچ‌چیز (ثبت‌نام، ورود، پیام) به آن وابسته نیست. اگر GitHub برای کاربرانتان مسدود است، به‌روزرسانی را می‌توانید خودتان فایل APK بدهید.

## چطور نسخه منتشر کنید

1. نسخه را در `client/android/VERSION` بالا ببرید (`ZG_RELEASE` عدد صحیح فزاینده و `ZG_VERSION_NAME` مثل `1.0.1`).
2. APK بسازید: `./client/android/build.sh` ← `client/android/out/zerogram-arm64-v8a.apk` و فایل `zerogram-arm64-v8a.apk.sha256`.
3. در GitHub یک Release با **تگ `v<ZG_VERSION_NAME>`** (مثلاً `v1.0.1`) بسازید و هر دو فایل را به‌عنوان asset ضمیمه کنید. نکته‌ها:
   - Pre-release و Draft نادیده گرفته می‌شود.
   - نام asset باید با `.apk` تمام شود و برای دستگاه‌های arm64 شامل `arm64-v8a` باشد (نسخهٔ بدون ABI در نام، «universal» حساب می‌شود).
   - چک‌سام از `digest` خودِ GitHub یا از asset هم‌نامِ `.sha256` خوانده می‌شود. **بدون چک‌سام برنامه نصب نمی‌کند.**
   - متن Release در صفحهٔ به‌روزرسانی نشان داده می‌شود.

## امنیت و کلید امضا

- برنامه قبل از باز کردن نصب‌کننده بررسی می‌کند: SHA-256 فایل = چک‌سام Release، نام بسته درست، **و امضای APK دقیقاً امضای برنامهٔ نصب‌شده است.** اندروید هم خودش نصب با امضای متفاوت را رد می‌کند.
- پس امنیت به کلید امضای شماست. `build.sh` آن را در اولین اجرا در `client/android/.keystore/` می‌سازد (بیرون از git). **پشتیبان بگیرید، هرگز commit نکنید، و کسی را بدون ضرورت به آن دسترسی ندهید.** هر کس این کلید و دسترسی نوشتن به Releaseها را داشته باشد می‌تواند «به‌روزرسانی» دلخواه به کاربران بدهد.
- اگر کلید را گم کنید، دیگر نمی‌توانید به‌روزرسانی روی نسخهٔ نصب‌شده بدهید (کاربران باید حذف و دوباره نصب کنند و تاریخچهٔ روی دستگاهشان از دست می‌رود). کلیدی که در مخزن اصلی Telegram هست عمومی است و برای زیروگرام استفاده نمی‌شود.
- نسخهٔ نصب‌شده با کلید دیگری (مثلاً APK آزمایشی قدیمی) را نمی‌توان با به‌روزرسانی عوض کرد؛ یک بار حذف و نصب لازم است.

## آزموده شده / نشده

- منطق مقایسهٔ نسخه، انتخاب asset، و بازهٔ بررسی در کد است؛ **اجرای کامل روی دستگاه (دانلود، بررسی امضا، نصب‌کننده سیستم) آزموده نشده** چون دستگاه یا شبیه‌ساز در محیط توسعه نبود و تا لحظهٔ نوشتن این سند Releaseی با APK در مخزن منتشر نشده بود.
