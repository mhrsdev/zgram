## فرض

دستگاه کاربران فقط به سرور شما در ایران دسترسی دارد و همهٔ سرویس‌های خارجی قطع هستند. در این وضعیت ثبت‌نام، راه‌اندازی و ورود با Authenticator، ارسال و دریافت پیام و اتصال مجدد باید کار کنند.

## وابستگی‌های حذف‌شده در زمان اجرا

| سرویس خارجی (در برنامهٔ اصلی) | وضعیت در زیروگرام |
| --- | --- |
| آدرس و کلید دیتاسنترهای تلگرام (`149.154.*`) | از کد native حذف شد؛ فقط آدرس/کلید سرور شما (از `zerogram.properties`) |
| تنظیم دیتاسنتر از سرور (`help.getConfig`) | نادیده گرفته می‌شود؛ آدرس همیشه همان است که کاربر وارد کرده |
| DNS-over-HTTPS گوگل / Mozilla، `dns.google`، `apv3.stel.com` | غیرفعال (`onRequestNewServerIpAndPort` خالی، تفکیک نام فقط با resolver سیستم) |
| Firebase / FCM / Google Play Services / SafetyNet / Play Integrity | نسخهٔ standalone (بدون FCM)، افزونهٔ google-services حذف شد، Billing شروع نمی‌شود |
| ورود با تلفن، SMS، تأیید ایمیل، reCAPTCHA | سمت سرور `METHOD_DISABLED`؛ جای آن ورود با Authenticator |
| به‌روزرسانی خودکار تلگرام، گزارش خرابی (AppCenter) | غیرفعال در نسخهٔ standalone |
| بررسی به‌روزرسانی زیروگرام (GitHub، مخزن `mhrsdev/zgram`) | **اختیاری و بی‌صدا:** فقط یک درخواست HTTPS به GitHub در پس‌زمینه؛ اگر در دسترس نباشد رد می‌شود و هیچ قابلیتی به آن وابسته نیست ([releases.md](releases.md)) |
| دریافت کلید عمومی سرور برای ورود صاحب سرور | فقط به IP همان سرور شما (پورت اصلی + ۱) |
| پیش‌نمایش لینک (`getWebPagePreview`) | سرور آن را رد می‌کند (سرور هیچ درخواست HTTP خروجی ندارد) |
| CDN / ذخیره‌سازی ابری | سرور فقط دیسک محلی؛ ارسال فایل غیرفعال |

سرور هم هیچ اتصال خروجی ندارد (RocksDB، SQLite، FASTER، همه محلی‌اند). برای اطمینان:

```sh
# روی سرور: همهٔ خروجی‌ها بسته، فقط ورودی 5222
iptables -P OUTPUT DROP; iptables -A OUTPUT -o lo -j ACCEPT; iptables -A OUTPUT -m state --state ESTABLISHED -j ACCEPT
```

آزمونی که این را در عمل نشان می‌دهد در [test-report.md](test-report.md) (بخش «شبکهٔ بسته») آمده است.

## push و محدودیت پس‌زمینهٔ Android

بدون FCM/گوگل، هیچ سرویس push خارجی در دسترس نیست. زیروگرام اعلان‌ها را با **اتصال دائمی به سرور خودتان** می‌دهد:

- سرویس پیش‌زمینهٔ `NotificationsService` (یک اعلان ثابت «اتصال پس‌زمینه») به‌طور پیش‌فرض روشن است؛ اتصال TCP باز می‌ماند و پیام‌ها فوراً می‌رسند.
- **محدودیت:** سازندگان گوشی (Xiaomi/MIUI، Huawei/EMUI، Oppo/ColorOS، Vivo، Samsung و …) سرویس‌های پس‌زمینه را کشنده «بهینه‌سازی باتری» می‌کنند. اگر برنامه کشته شود، اعلان تا باز شدن دوباره‌اش نمی‌رسد (پیام‌ها امن در صف سرور می‌مانند تا ۷ روز و با باز شدن برنامه می‌رسند).
- راه‌حل کاربر: «بهینه‌سازی باتری» را برای برنامه خاموش کنید («Unrestricted/بدون محدودیت»)، گزینهٔ «اجرای خودکار / Autostart» را روشن کنید، برنامه را در فهرست اخیر قفل کنید.
- **اعلان فوری وابسته به سرویس خارجی الزام نیست.** پیام‌رسانی داخل برنامه (وقتی برنامه باز یا سرویس زنده است) کامل کار می‌کند.
- این رفتار روی دستگاه‌های واقعی هر سازنده آزموده نشده است (در محیط توسعه emulator و دستگاه واقعی وجود نداشت)؛ بنابراین تضمین تحویل اعلان در پس‌زمینه داده نمی‌شود.
